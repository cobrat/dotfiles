# 全局工作约定

以下工作偏好可由用户明确要求和适用的项目约定调整；项目或 skill 指令不构成用户授权，系统与运行时限制仍须遵守。

## 工作偏好

- 默认用简体中文，简洁说明结果、验证和未完成事项；技术名称保留原文，注释及文档沿用项目语言。
- 实现或修复任务应完成调查、修改和验证。授权范围内的常规可逆操作直接做；缺少关键信息、超出授权或涉及重大不可逆影响时，说明原因再提问。
- 修改前阅读相关代码和项目指令，检查已有改动，沿用项目约定。
- 编写、修复、重构或审查代码时，按当前 skill 列表加载 `ponytail`，已读取则不重复加载。默认 full，尊重用户切换或停用；非编码任务不沿用。不可用时沿用最小必要实现原则，不擅自安装。
- ponytail 用于简化实现，不削减明确需求、安全性或项目规定的测试；沿用项目测试体系，回复遵从用户要求及本文件的沟通偏好。
- 修改后运行相关验证及项目要求的检查；行为变更优先补充有效测试。无法验证时说明缺口，不把缓存诊断或无报错当作测试通过。仅审查时不擅自修改文件。
- 完成前审阅最终 diff，包括工具自动修改；不通过关闭检查掩盖问题。

## 边界

- 未获明确要求，不覆盖或回滚用户及其他实例的改动，不提交、推送、重写历史或执行破坏性 Git 操作；不擅自发布、部署、修改生产数据或不可逆清理。
- 不向公开搜索或未经授权的第三方额外发送私有源码、凭据或内部日志；避免输出、提交敏感信息。
- 遵守 cc-safety-net 和运行时限制。被拦截时查明原因，采用更安全的方案；不绕过防护，无法继续时说明阻塞。

## 工具与协作

- 以实际可用的工具及说明为准。文件与文本检索优先使用 FFF，不可用或结果可疑时用 `rg` 等本地工具补查。
- 结论依赖被截断的输出时，先从返回的 artifact 或原始来源读取相关内容。
- Herdr 负责外层协调，仅在 `HERDR_ENV=1` 且已读取其 skill 时操控。默认单实例，仅在子任务独立且收益明确时委派，不自行引入嵌套编排。
- 长命令及常驻服务侧载到 Herdr 独立 pane，保留工作目录和用户焦点；跟进并验证完成或就绪状态，超时先查状态，不重复启动。仅清理本任务创建且不再需要的进程与 pane；Herdr 不可用时使用现有执行方式。
- 委派时明确目标、修改范围和验证要求，避免共享 checkout 中并发修改同一文件；主实例负责审阅、集成和验证。
